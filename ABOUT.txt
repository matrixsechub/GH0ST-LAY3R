## ⚡ Overview

The **Ghost Layer Cosmology Engine (GLCE)** is a Python-native simulation framework engineered to model large-scale cosmological structures — dark matter halos, baryon acoustic oscillations, void formation, and inter-filament dynamics — across multi-resolution spatial grids with sub-grid ghost-layer propagation.

At its core, GLCE introduces the concept of **ghost layers**: phantom computational boundary zones that propagate physical state information across domain partitions without artifacts, enabling seamless multi-process cosmological runs at scales previously reserved for HPC clusters. The engine is designed to be run locally, headlessly, or as a distributed pipeline — and exposes both a clean Python API and a full CLI operator interface.

This is not a toy simulator. GLCE is built for those who need:

- **Repeatable, deterministic** simulation runs with version-locked seeds
- **Modular physics kernels** that can be swapped, stacked, or extended
- **Operator-grade observability** through structured logging, telemetry hooks, and run manifests
- **Export pipelines** to FITS, HDF5, NumPy, and custom binary formats for downstream analysis

## 🏗️ Architecture

GLCE is organized around four primary subsystems that compose the full simulation pipeline:

```
┌─────────────────────────────────────────────────────────────┐
│                    SimulationEngine                         │
│  ┌──────────────┐  ┌─────────────────┐  ┌───────────────┐  │

│  │  Domain      │◄─►  Exchange       │  │  Model        │  │
│  │  Partitioner │  │  Propagator     │  │  (ΛCDM / wCDM)│  │
│  └──────┬───────┘  └────────┬────────┘  └───────┬───────┘  │
│         │                   │                    │          │
│         └──────────┬────────┘                    │          │
│                    ▼                             ▼          │
│           ┌────────────────┐          ┌──────────────────┐  │
│           │ Physics Kernel │          │  Telemetry &     │  │
│           │ Stack          │          │  Audit Layer     │  │
│           │ gravity        │          │  (per-step)      │  │
│           │ hydro          │          └──────────────────┘  │

└─────────────────────────────────────────────────────────────┘
```

### Ghost Layer Mechanics

Ghost layers are thin computational halo zones appended to each domain partition boundary. On every timestep:

1. **Padding** — each partition's boundary cells are duplicated into adjacent ghost zones
2. **Exchange** — ghost zone data is broadcast to neighboring domains via the `GhostExchange` protocol
3. **Propagation** — the `GhostPropagator` resolves state conflicts using weighted interpolation
4. **Validation** — the `GhostValidator` audits conservation laws across all ghost boundaries before the next kernel pass

This architecture eliminates domain-edge artifacts in N-body gravity calculations and ensures SPH particle interactions remain coherent across partition lines without requiring a global lock.

### Kernel Stack Execution Order

Each simulation step executes the kernel stack in a deterministic sequence:

```
Step N:
  [1] Gravity Kernel     — long-range force computation (PM or TreePM)
  [2] Hydro Kernel       — pressure, density, velocity updates (SPH/grid)
  [3] Radiation Kernel   — photoionization, heating/cooling
  [4] Dark Energy Kernel — scalar field evolution, equation of state
  [5] Baryon Kernel      — star formation, feedback, chemical enrichment
  [6] Ghost Exchange     — boundary state synchronization
  [7] AMR Refinement     — adaptive grid restructuring (if triggered)
  [8] Telemetry Flush    — metrics, energy audit, divergence check
  [9] Snapshot (if due)  — I/O pipeline write
```

Kernels are independently toggleable and orderable via configuration.

## 🚀 Quick Start

### Minimal Python API Run

```python
from glce import SimulationEngine
from glce.cosmology import LCDMModel, CosmologicalParameters
from glce.kernels import GravityKernel, HydroKernel
from glce.io import HDF5Writer

# Define cosmological parameters
params = CosmologicalParameters(
    H0=67.4,        # Hubble constant (km/s/Mpc)
    Omega_m=0.315,  # Matter density
    Omega_L=0.685,  # Dark energy density
    sigma8=0.811,   # Power spectrum normalization
    n_s=0.965,      # Spectral index
)

# Build and configure the engine
engine = SimulationEngine(
    cosmology=LCDMModel(params),
    box_size=100.0,             # Comoving Mpc/h
    n_particles=512**3,
    ghost_depth=2,              # Ghost layer depth (cells)
    seed=42,
)

# Attach physics kernels
engine.add_kernel(GravityKernel(method="TreePM", softening=0.02))
engine.add_kernel(HydroKernel(scheme="SPH", gamma=5/3))

# Attach output writer
engine.add_writer(HDF5Writer(output_dir="./output", snapshot_interval=0.1))

# Run from z=99 to z=0
engine.run(z_start=99.0, z_end=0.0)
```

### CLI Operator Interface

```bash
# Run a simulation from a YAML config file
glce run --config configs/lcdm_default.yaml

# Dry-run to validate config and print the execution manifest
glce run --config configs/lcdm_default.yaml --dry-run

# Inspect a snapshot file
glce inspect output/snapshot_z0.00.hdf5

# Validate a config file against the schema
glce validate configs/wcdm_dark_energy.yaml

# Run with verbose structured JSON logging
glce run --config configs/lcdm_default.yaml --log-format json --log-level DEBUG
```

### YAML Configuration

```yaml
# configs/lcdm_default.yaml

cosmology:
  model: LCDM
  H0: 67.4
  Omega_m: 0.315
  Omega_L: 0.685
  sigma8: 0.811
  n_s: 0.965

simulation:
  box_size: 100.0         # Comoving Mpc/h
  n_particles: 256        # Particles per side (256^3 total)
  z_start: 99.0
  z_end: 0.0
  seed: 42

ghost_layer:
  depth: 2
  exchange_protocol: mpi  # options: local, mpi, ray

kernels:
  - name: gravity
    method: TreePM
    softening: 0.02
  - name: hydro
    scheme: SPH
    gamma: 1.6667
  - name: dark_energy
    enabled: true

output:
  format: hdf5
  output_dir: ./output
  snapshot_interval: 0.1   # in redshift steps
  fields: [position, velocity, density, temperature]

telemetry:
  energy_audit: true
  divergence_threshold: 1.0e-5
  log_format: json
```

## 🔌 Extending GLCE: Custom Kernels

GLCE's hook and kernel systems are designed for rapid extension. To author a custom physics kernel:

```python
from glce.kernels.base import AbstractKernel
from glce.grid import GridPatch
import numpy as np

class ScalarFieldKernel(AbstractKernel):
    """Example: massless scalar field (axion-like dark matter)."""

    name = "scalar_field"
    priority = 45  # execution order in kernel stack

    def __init__(self, mass: float = 1e-22):
        self.mass = mass  # eV/c², ultra-light axion range

    def step(self, patch: GridPatch, dt: float, cosmology) -> GridPatch:
        a = cosmology.scale_factor
        phi = patch.fields["phi"]
        dphi = patch.fields["dphi"]

        # Klein-Gordon equation on expanding background
        laplacian_phi = np.gradient(np.gradient(phi))
        ddphi = -3 * cosmology.H(a) * dphi - (self.mass / cosmology.hbar)**2 * phi + laplacian_phi / a**2

        patch.fields["phi"]  += dphi * dt
        patch.fields["dphi"] += ddphi * dt
        return patch

    def validate(self, patch: GridPatch) -> bool:
        return np.all(np.isfinite(patch.fields["phi"]))
```

Register and activate:

```python
engine.add_kernel(ScalarFieldKernel(mass=1e-22))
```

## 📡 Output & Export

GLCE supports multiple output formats and a real-time streaming interface:

| Format | Extension | Notes |
|---|---|---|
| HDF5 | `.hdf5` | Default; full field snapshots with metadata |
| FITS | `.fits` | Astropy-compatible; ideal for sky-plane projections |
| NumPy Archive | `.npz` | Lightweight; fast I/O for post-processing |
| Binary Dump | `.glce.bin` | Custom packed binary; fastest write throughput |
| Stream | — | Real-time snapshot push to subscriber callbacks |

```python
from glce.io import FITSWriter, StreamWriter

# Export projected sky maps as FITS
engine.add_writer(FITSWriter(output_dir="./fits_output", projection="z"))

# Stream snapshots to a custom handler
def on_snapshot(snapshot):
    print(f"Snapshot at z={snapshot.redshift:.3f}: {snapshot.n_particles} particles")

engine.add_writer(StreamWriter(callback=on_snapshot))
```
